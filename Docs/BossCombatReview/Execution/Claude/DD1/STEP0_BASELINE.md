- `pie_damage_path` M2 (A5 javelin 0 of 5): ROOT CAUSE FOUND in source, a defect of my own test switch: `URPGBossDormantWake::BeginWake()` returns early when `rpg.WakeClip` is 0 (`RPGBossDormantWake.cpp:99-105`) BEFORE `StopClips(...)`, so the authored dormant LOOP montage is never stopped on an awake boss. The tracker then is not neutral (`IsNeutral()` needs no active montage), and the unforced A5 punish is refused: the log shows `heal 1 ignored: the boss is not in a state that may start a move (None)` in the M2 trials. Production (`rpg.WakeClip` 1) is not affected (`BeginWake` calls `StopClips` first); Shipping compiles the switch out. The older drivers that run with `rpg.WakeClip 0` were therefore running with a looping dormant montage on an awake boss since B11. Fix (Development-only test switch): in the `WakeClip == 0` branch stop the dormant montage before returning false (`RPGBossDormantWake.cpp`, preimage stored, edit written, NOT BUILT). Consequence for the baseline: the 36 passing rows ran with this latent defect; after the fix the gate is rerun in full and any row that changes is explained against this note (expected: `pie_damage_path` M2 passes).
