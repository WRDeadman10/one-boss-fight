## Behaviour
Game thread only (off-thread: refused before any UObject access and the output is NOT touched: releasing its leases off the game thread would be unsafe; this is the one carve-out from "clear the output on failure"). Then the output is cleared. World/binding validation (binding in that world, not being destroyed/begun/beginning, explicit valid GUID, participants, 64-hex manifest hash); selection coverage exactly one-to-one with no duplicate/empty/extraneous selection, explicit role, BossCore needs a phase and TargetOnly has none; members: actor valid/in world/not begun/unique, explicit target present/not self/in batch, definition present and schema 1 with ids (a definition may be shared between members; each member needs one). All structural problems are collected; any ends the call before content is acquired. Content: ONLY `RPGCombatRegistry::ForWorld(ExpectedWorld)` (the game instance and its catalog subsystem are also held for identity and required to report the same epoch pointer); no game instance / subsystem / epoch = `WorldInput.NoContent`; no Legacy(), injection or cvar. The epoch lease, the world, the game instance, the subsystem and the participant snapshot are rechecked before and after every `CompileParticipant` and before publication (`WorldInput.ContentDrift`, `WorldInput.BindingDrift`). `CompileParticipant` runs for every definition (it LOADS the declared skeleton and animations: stated against the load-free preflight), a production config (not synthetic, holding the acquired lease) is required, the whole candidate goes to `CompilePreflight`, nested diagnostics are carried unchanged (`WorldInput.DefinitionRejected[slot=..]: <nested>`, `WorldInput.PreflightRejected: <nested>`), and the output is published only on full success. Nothing else runs: no callback, component, registration, preparation, BindEncounter, context, reservation, Ready, legacy suppression, hook or write.
