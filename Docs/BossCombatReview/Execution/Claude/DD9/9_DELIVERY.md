## What it does

- Two reflected records on `URPGBossDefinition`, copied into `FRPGParticipantConfig` by the one shared `CompileParticipantImpl`: `FRPGFireballConfig` (`bFireballEnabled` false, `FireballAbility` soft class, `FireballCooldown` FVector2D (6, 10), `FireballMinRange` 500, `FireballMaxRange` 1800) and `FRPGPhaseDependencyConfig` (`RoarClip`, `TransitionMontage`, `ImmunityEffect` soft references). Names and defaults equal the native `URPGBossPhases` constructor; they are additive authoring defaults, never a fallback.
- Validators: fireball numbers finite, then not negative, then cooldown minimum not above maximum, then range minimum not above maximum, then the ability (required only when enabled; a set path must be a well-formed class path). Dependencies: path STRUCTURE only (starts with `/`, no whitespace or control characters or sub-object, `<package>.<asset>`, a package folder, class paths end in `_C`), no registry query, no load; the roar clip is required when `bUseRoarClip`, the montage when it is the roar instead, the immunity effect always.
- `ConfigurePhasesCluster`: accepted lifecycle checks, then `ValidatePhases` + `ValidatePhaseFlow` + fireball + dependencies, then ONE write block of 18 fields (selected phase 4, flow 6, fireball 5, dependencies 3). `MakePhasesClusterPlan(SelectedId)`: unwired plan, legacy instance name `RPGBossPhases`, 18 required paths.
- Not done here: wiring, preflight insertion, activation, asset existence or class-kind checks, the stagger profile, any pack edit.

## Judgement calls (the lead decides)

1. The immunity effect is REQUIRED (no silent absence); the roar clip is required only when used and the montage only when it is the roar. 2. Cooldown and range order violations are refused (the native code would hide an inverted cooldown by using the minimum for both). 3. Zero is valid for every number; no ceiling. 4. A set but malformed path is refused even when the field is optional or unused. 5. The lifecycle check is restated a sixth time (accepted files unchanged). 6. Path structure only: existence, cooking, class kind and clip fit are unresolved integration checks.

## Lead review (Claude, with an independent read-only sub-agent pass) and the changes it caused

The independent pass found nothing that should fail to compile or fail UHT (it checked the 5.5.4 headers for every constructor and overload used) and traced every `Check(...)` and `Bad[]` case against the code. Findings and decisions:
1. Header comment said "five numbers", there are four: FIXED. 2. Header comment overclaimed that a record accepted by the two older adapters is accepted by the cluster (the fireball and dependency checks are additional): REWORDED. 3. Native C++ class paths (`/Script/<Module>.<Class>`) were refused by the `_C` rule: DECIDED to accept them for the two class-valued fields (a native class is a legitimate soft class reference); `PathProblem` and two new test cases (ability and immunity as a `/Script/` path, plus a `/Script/` path with a sub-object still refused) were added; the other path characters the engine would reject (`* ? |`) stay unscreened and are documented. 4. The "nothing loaded" test could pass vacuously for an asset already in memory: STRENGTHENED with the package presence (`FindPackage`) before and after; the remaining limit (an asset that is already loaded proves nothing for its own path) is stated in the test and goes into KI-115. 5. The compiler does not run `ValidatePhases` (pre-existing, DD4 era): a definition with a damage multiplier below 1 compiles but the cluster assignment refuses it; recorded as a limit for KI-115, not changed here. 6. A null `TransitionMontage` is accepted when the roar clip is used (it is only the fallback): DECIDED to keep, stated as a judgement call.
Weak spots to watch at build time: `FClusterState::RuntimeEquals` compares mostly constructor defaults (the runtime fields are private), and `static_cast<float>` of NaN or infinity in the tests could draw an MSVC constant-conversion warning (not expected; count `warning C` exactly).

## Failure found by the AG-1 full run (A-155) and its fix: a defect of my test file, kept on record

The first full run (88 found) had 87 Success and 1 Fail: `OneBossFight.Content.CookCoverage` (`RPGAutomationTests.cpp` around line 1300) scans every `.cpp`/`.h` under `Source/OneBossFight` for quoted `"/Game/..."` literals and requires each to lie under a `DirectoriesToAlwaysCook` directory, because a literal that is loaded by path must be cooked. My DD9 test file used 17 distinct synthetic `/Game/...` paths (fixtures, never loaded, most of them deliberately nonexistent), so the rule flagged them. The seven new PhasesCluster tests passed. Fix (lead decision): rename the synthetic mount in the test file only, `"/Game/` -> `"/SyntheticMount/` (28 occurrences); no change to the CookCoverage test, to any cook list, to a filter or to production code. The paths remain structurally valid (they start with `/`, `<package>.<asset>`), so no test expectation changes. The failing evidence of the first run stays in `build_2026-10-27/` (AG-1's `automation_full_dd9.log`, sha256 `43246f4d...dfb0`); the rerun uses new tags and a new editor DLL.
