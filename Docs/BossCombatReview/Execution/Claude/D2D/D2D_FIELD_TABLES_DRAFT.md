## How each row is used by 2d

- **Apply timing**: content and policy fields are applied by a typed `ConfigureBeforeRegistration` adapter BEFORE `RegisterComponent` (the components read their fields in the constructor and `BeginPlay`; Boss01 values must be in place at registration). Runtime state/caches are never in a definition and are not applied.
- **Parity assertion (generic, per property)**: an automation test constructs the component with `NewObject`, reads each reflected property by name and compares it with the adapter value produced from the Boss01 definition built from the SAME compiled defaults; plus the per-component driver listed in `Codex/PROMOTION_STEP2.md` run before and after. A property whose default is `(uninitialized here)` needs the constructor/serialized override read first (column `Default`).
- **Order**: adapters keep the live registration order (the tables below are in that order): Stagger, Phases, Encounter, DormantWake, Posture, Death(OwnClip), Look, Bleed, AttackTracker, CloseClipSwap, Shockwave, LowSweep, HealPunish, Hud (DamageResolver/TraceGuard/TraceAudit/CombatDebug/Legend carry no Boss01 content fields in the manifest and are invariants of the compatibility path).

## Rules used for the proposal column

1. Names matching `Loaded*`, `*Component(s)`, widget pointers, `Encounter/Phases/Posture/Stagger` back-pointers, `Materials`, `HiddenPackWeapons`, `OnVictory` = runtime state or cache.
2. `ASSET_REFERENCE_DEFAULT` rows and every `NEEDS_EDITOR` row = asset reference content; the effective value needs the editor readback (skeleton, length, class ancestry), export text is not a live value.
3. `NSLOCTEXT(...)` defaults = presentation text.
4. Names ending `ClassName`, `MontagesName`, `AbilityPrefix`, `AbilityTag`, `Socket`, `MoveId`, `MontageName` = pack ABI strings (invariant of the reference pack).
5. `bEnabled`, `bTest*`, `bGuard*`, `bUse*`, `bPin*`, `bLock*`, `bHide*`, `bRespond*`, `bCancel*`, `bCritical*`, `bHold*`, `bPause*`, `bFireball*`, `bResetOn*`, `bVeto*`, `bAuthored*`, `bBranch*`, `DeathMode` = policy or test flag: each needs a decision (Encounter policy vs test-only vs invariant).
6. Names containing time, speed, range, radius, damage, scale, fraction, threshold, multiplier, degrees, height, gap, clearance, reach, thickness, count, max/min = tuning number.
7. Anything else = `REVIEW`.

Not covered here (still OPEN, by design): the `.cpp` literal rows (move timing tuples, state seeds, diagnostics) that the manifest marks `NEEDS_SEAM`; they need the seam decision per row (content vs invariant) before any table row can be written for them. `AttackTracker.cpp` lines 33 to 63 (A2 commit 1.68, active 1.93..2.11, recovery 3.14; the four exact `AddClose` tuples) are code-observer compatibility timings, not to be overwritten from the sidecar.
