### (superseded) A hazard I found in the EARLIER test files (not changed, reported)

Four existing test files have a file-scope using-directive: `RPGBossStatsAdaptersTests.cpp` (`StatsAdapterTests`), `RPGBossPhaseAdaptersTests.cpp` (`PhaseAdapterTests`), `RPGBossHydrationPreflightTests.cpp` (`PreflightTests`) and `RPGBossEncounterPolicyAdaptersTests.cpp` (`PolicyTests`). Several of them define functions and constants with the same names inside their own namespaces: `MakeField` and `AnyErrorContains` (Preflight and Policy), `MakePhase` (Phase and Preflight), `QuietNaN` and `PosInf` (Phase and Policy), `ArmSentinels` and `MakeConfig` (Policy and, now, Stagger). Today these files are untracked, so the adaptive build compiles each in its own translation unit and the names never meet. Once they are committed they become members of the module's unity files, and two file-scope using-directives that expose the same function or constant name in one translation unit make an unqualified use ambiguous (identical type aliases such as `FEpochPtr` name the same type and are not a problem). This is a source-analysis conclusion; I have NOT reproduced it with a unity build and did not edit any accepted file. A mechanical fix would move each `using namespace` into the test bodies, as the new file does; I leave that to your decision as a separate, reviewable change.
