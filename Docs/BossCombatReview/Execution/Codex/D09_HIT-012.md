# BOSS-HIT-012 — boss grab lifecycle (WP-5/2)

REQUIRED, DESIGN ONLY, 2026-10-25 Codex. Size LARGE. Current D03 UNVERIFIED; a player riposte is not a boss grab proof. WP4 supplies pre-play action identity, paired reservation and finalizer; QA008 supplies authority. No content or implementation authored.

## Assumptions

Smallest conforming grab is one boss-initiated paired capture with explicit startup tell/contact, finite hold/impact/release and fallible range/facing/defense gates. No escape minigame or instant unavoidable teleport is invented. Reverse by disabling this move only before encounter startup until accepted, not by leaving captured actors disabled.

Shared RPGPairedActionExecutor plus RPGGrabContactResolver, not per-boss GrabComponent. Before reservation server validates both actors/current generations/targetability/dodge/guard policy and occupancy. Reserve both lanes atomically; failure releases both. Capture only during accepted contact window; once confirmed, align within declared caps and obstacle-safe placement. Impact keyed by action/marker/target once; no duplicate notify damage. Death/reset/stagger/phase policy/disconnect/despawn/failed playback/timeout/missing notify all reach idempotent SafeRelease. Restore only owned handles and safe floor/nav/collision pose; do not globally enable input that another system still owns. Delayed events fail generation tests.
