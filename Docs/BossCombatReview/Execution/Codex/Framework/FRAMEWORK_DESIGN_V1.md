## 2. Canonical new data and runtime contracts (all PROPOSED)

Data Assets / Details first, no custom wizard now. Proposed URPGBossMoveCard is a new asset type (not existing) with explicit MoveId/FamilyId, exact Sevarog animation or montage, expected skeleton, explicit playback slot/section, authored timing windows, turn/commit rule, hit groups/shapes/socket references, phase/eligibility constraints and recovery. Exactly one animation source per card; no guessed default fallback. Existing stats/phase records remain single-owner. New cooldowns are not fabricated from old A1/A2/A3: do not duplicate existing Fireball/HealPunish/Stagger cooldown fields. First slice uses authored recovery/neutral unlock only; a later generic per-move cooldown would be an explicit NEW design rule with a real selector consumer.

Compiler yields immutable runtime MoveCard/profile and retained asset leases, with named errors before any runtime write. Require nonempty unique IDs and valid referenced skeleton/animation/slot/socket identities; finite seconds/angles/ranges, ordered0<=commit<=activeStart<activeEnd<=recoveryEnd<=clip end in montage-local time, strictly positive play rate, existing project's finite1e6 ceiling discipline. Multiple windows, swept geometry shape dimensions and hit-group semantics are validated explicitly; closed inactive intervals cannot damage. No clamp, arbitrary constructor substitution or Value-text import. These are proposed domains, not existing validation or authorised numeric tuning. The initial card cannot execute until ALL required values are authored/reviewed; an empty/default asset is disabled with error.

Runtime snapshot has explicit world/encounter/generation/actor weak identities and target lease resolution, clock and decision facts. Executor uses monotonic attack-instance IDs coupled to encounter generation; opens/closes windows from montage-local time with interval-crossing handling (a long frame cannot skip the entire damage window or double-fire). Commit freezes permitted heading; actor motion is collision-aware and separately owned. A contact carries instance+generation+window/group+target; accepted damage spends the hit once, rejected i-frames do not, consistent with existing resolver. Single executor owns tick/timer/notify callbacks; callback generation/instance mismatch is ignored and audited. All end/abort/interrupt/reset/death paths close windows, stop owned playback/motion, invalidate delayed work and clear hit state once. No blend-out callback may restore an obsolete attack.
