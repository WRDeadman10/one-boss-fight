# Queue F-C C2 tasks 16–20: receipts and dispatch

The C2 actions now share `receipt_schema.py`, which normalizes the receipt fields and serializes compact, sorted JSON under schema `c2.validate-boss.receipt.v1`. The AnimBlueprint action emits `compile_selected_anim_blueprint`; its `compiled` flag indicates that the compile action was attempted, while `saved` remains false. Its fields report the compile API, attempt, and generated-class path; compiler errors come from newly appended `[Compiler]` log lines. It does not read the protected Blueprint `status` property. Profile preflight emits `preflight_selected_boss_profile` and reports `compiled=false`, `saved=false`.

`run_validate_boss.py` is the single Content Browser entry point. It accepts exactly one `RPGBossFrameworkProfile` or `AnimBlueprint`, routes to the existing action, and emits structured selection diagnostics for zero, multiple, or unsupported selections. `fixtures/dispatch_cases.json` records those selector cases for later automation integration.

Acceptance boundary: receipts are machine-readable and have stable schema/action metadata; dispatch maps only the two supported classes; both underlying actions retain their existing validation behavior. The AnimBlueprint action compiles only the selected blueprint and does not save. The profile action checks the C1 offline mirror and does not call the native framework validator, compile, or save. Compiler log attribution remains best-effort. No Unreal Editor, PIE, build, or test run was performed by Codex; Lead runtime review is still required.

Pure receipt/dispatch contract coverage is in `test_receipt_schema.py`; the initial local run passed 3/3. `test_anim_blueprint_compile_failure_context.py` covers compiler failure context and clean compile evidence without reading Blueprint status. The fixture covers empty and multiple selections, both supported classes, unsupported types, stable receipt defaults, and deterministic JSON serialization.
