### 2.2 How the pack applies damage to the player (read through the editor bridge, blueprint_query get_nodes/inspect, read-only)
Chain for a pack weapon trace (boss GS_* montages):
1. ANS_CollisionTrace drives BP_EnemyAbilitySweepingTraceTarget (parent BP_AbilitySweepingTraceTarget, parent BP_SweepingSocketTraceTarget, parent BP_TraceTarget, parent BP_TargetType). BP_TraceTarget EventGraph "CollisionTrace": multi sphere trace -> for each hit "Can Hit Actor?" -> Branch -> "Add Hit Actor" (per-swing hit set) -> "On Hit".
2. BP_TargetType "Can Hit Actor?" (CollisionSystem/BP_TargetType graph): not the performing actor, not already in HitActors ("Hit one enemy only once" comment), collision profile and actor class ignore lists, and "Has Any Matching Gameplay Tags" (BP_GameplayTagBlueprintInterface message) of the hit actor against variable GameplayTagsToIgnore, ANDed with "Can Hit Component?". The strings "Status.Dead" and "Status.Invulnerable" appear in BP_TraceTarget.uasset (offsets 6611, 6631) and BP_EnemyAbilitySweepingTraceTarget.uasset (offsets 1267, 1287) right after the name GameplayTagsToIgnore (parsed). So the pack most likely rejects an invulnerable target AT THE TRACE FILTER, before hit data, impact decision, damage execution or hit reaction. Default value of GameplayTagsToIgnore: UNVERIFIED (the bridge get_variables does not return defaults). Consequence for the Freeze 10.1 table: for pack moves the trace decides invulnerability (the thing the Freeze lists as not wanted) but it reads the same tag as the receiver, so the result is consistent.
3. BP_AbilitySweepingTraceTarget "OnHit": Make Hit Event Data, "Run State Machine by Tag" StateMachine.ImpactDecision on the target's state manager (MeleeCombatSystem/Blueprints/States/SM_ImpactDecision), then Hit Handle (BP_DamageInterface message) to the performing actor, then SendHitEventToAbility (Gameplay Event Received on the attack ability), then hit impulse.
4. SM_ImpactDecision (read): WasAttackBlocked? = target has Status.Blocking AND hit angle in range -65..65 inclusive AND CanAttackBeBlocked? (not IsUnblockable on BP_HitData) AND AllowedImpactDecisions has ImpactDecision.BlockedHit; WasAttackParried? = Status.ParryActive AND distance <= Minimum Parry Distance AND Can be Parried AND ImpactDecision.ParriedHit allowed; WasAttackDeflected? = InputTag.Block held time <= Deflection Timing AND ImpactDecision.DeflectedHit allowed. The result is BP_HitData.ImpactDecisionTag.
5. Damage is a gameplay effect (GE_MeleeDamage etc., parent GE_DamageBase, which has "ExecuteGameplayCues") run by BP_MeleeDamageExecution (parent BP_DamageExecution). BP_DamageExecution EventGraph: Cast GE to GE_DamageBase, set attribute components, "Can Damage be Applied?" (checks DamageImmuneTags, default value of that variable contains the tag Status.DamageImmune, offset 8654, parsed; and the hit data's ImpactDecisionTag), PreCalculationBonus, CriticalDamage, PostCalculationBonus, DamageResist, then "Deal Damage". BP_MeleeDamageExecution "Deal Damage": Switch on Gameplay Tag (ImpactDecisionTag); blocked branch reduces stamina (Attribute.Stamina, scaled by Attribute.Stability) and health (scaled by Attribute.BlockPhysicalDamageReduction), else Modify Attribute Attribute.Health by -Damage; then "On Damage Applied" (BP_DamageInterface). Exact formulas: UNVERIFIED (I read node names, not every pin link).
6. Hit reaction: GE_DamageBase executes a gameplay cue; BP_Character_DamageTaken (GameplayCues) EventGraph OnExecute -> "On Damage Taken": "Has Any Matching Gameplay Tags" with container (Status.Dead, Status.Invulnerable) on the owner, and only when NOT true it calls "Activate Damage Taken Ability" (also camera shake via BP_ImpactEffect). ActivateDamageTakenAbility: ASC "Get Abilities By All Tags" Ability.HitReaction -> cast GA_BaseHitReaction -> "Set Hit Data" -> "Try Activate Ability". So the hit reaction has a SECOND invulnerability check, on the cue. GA_HitStun (parent GA_BaseHitReaction) ActivateAbility: Commit, Enter State Character.State.Hit.Stun, Get Ability Montage, Play Ability Montage (stop all), hit-count timer 5 s, optional rotation to face the applier and directional knockback. GA_BaseHitReaction "Can Activate Ability?" requires valid hit data and, when bUsesPoise, drains Attribute.Poise (-20 base, -30 more for attack power >= 3, so heavy = -50) and gates the flinch on poise <= 0 (read, pin values partly unverified).
7. Where the pack checks Status.Invulnerable (binary string search over Content/AdvancedARPGCombat/AdvancedCombatFramework and MeleeCombatSystem/Blueprints): ANS_iFrames, BP_TraceTarget, BP_EnemyAbilitySweepingTraceTarget, BP_Character_DamageTaken, DT_CoreCombatGameplayTags, BP_EnemyDeathTask (sets or reads it on enemy death, unverified). Status.DamageImmune appears only in BP_DamageExecution and the tag table. So Status.Invulnerable is NOT checked inside BP_DamageExecution itself: with the trace filter bypassed (our moves), the pack damage execution would hurt an invulnerable target.
8. The pack's interface functions on the pawn: BP_GameplayTagBlueprintInterface functions GetOwnedGameplayTags, HasMatchingGameplayTag, AddOwnedGameplayTag, RemoveOwnedGameplayTag, AppendToOwnedGameplayTags, RemoveOwnedGameplayTags, HasAnyMatchingGameplayTags, HasAllMatchingGameplayTags. The tag container is a plain variable GameplayTags on BP_BaseCombatCharacter (variables list read). It is a container, NOT reference counted.

### 2.4 Engine behavior that matters (UE 5.5 source, C:/Program Files/Epic Games/UE_5.5/Engine/Source/Runtime/Engine/Private)
- Montage time is advanced by the sub-stepper from DeltaTime * play rate (Animation/AnimMontage.cpp:2427-2477 FAnimMontageInstance::Advance, MontageSubStepper.AddEvaluationTime(DeltaTime)), so the position in montage seconds does not depend on frame rate. What depends on frame rate is when a notify is OBSERVED: notifies are queued for the range crossed in a step and dispatched in UAnimInstance::TriggerAnimNotifies (Animation/AnimInstance.cpp:1548-1642), NotifyBegin for states new in the queue (1628-1640), NotifyEnd for states no longer in the queue (1598-1611). So the observed begin/end is quantized to one frame (up to dt * rate montage seconds late), never early.
- Order in one anim update: TriggerAnimNotifies (AnimInstance.cpp:778) then TriggerQueuedMontageEvents (781). A montage that ends or is stopped gets NotifyEnd for ITS notify states in TriggerMontageEndedEvent (2088-2125), matched by MontageInstanceID (so ending montage A cannot end a state of montage B, but the end runs when the stopped montage finishes BLENDING OUT, not when the new montage starts).
- Other end paths: AnimInstance.cpp:355-384 ends all active notify states and resets the list (function name not confirmed: unverified which teardown it is; it is the path "montage instances deleted" at 340-350).
- Notify timing API: FAnimNotifyEvent::GetTriggerTime/GetEndTriggerTime/GetDuration (Animation/AnimTypes.cpp:82-100); the editor python helper already used in this repo is unreal.AnimationLibrary.get_animation_notify_events(montage) (Scripts/Editor/inspect_pack_notifies.py:21-35).
- Frame rate control: CVar t.MaxFPS is read in UEngine::GetMaxTickRate (UnrealEngine.cpp:11627-11671) and UEditorEngine::GetMaxTickRate returns the Super value when not throttled (EditorEngine.cpp:2486-2500), so t.MaxFPS works in PIE if editor throttling is off (Scripts/Editor/no_throttle.py). Better for deterministic dt: UEngine::bUseFixedFrameRate + FixedFrameRate (Classes/Engine/Engine.h:1527-1536); UpdateTimeAndHandleMaxTickRate (UnrealEngine.cpp:2699, 2769-2785) forces dt = 1/FixedFrameRate even when the frame costs more (the process "falls behind real time"). Repo precedent for saving and restoring these: Source/OneBossFight/Benchmark/RPGBenchmarkRunner.cpp:374-424.

## 4. Design (working notes, to be finalized)
- New component URPGBossDamageResolver on the boss (attached in RPGPlayerMovesSubsystem::Attach next to the others, so drivers can use comp(boss, "RPGBossDamageResolver")), plus struct FRPGDamagePayload {SourceMove FName, AttackInstance int32, HitStage int32 (default 0), Generation int32, Target AActor*, HealthDamage float, PostureDamage float (always 0 for boss moves, Freeze 504), GuardStaminaDamage float, bCanBeBlocked bool, ReactionTier enum {None, Flinch, Stagger, Knockdown}, SourceLocation FVector, bBypassInvulnerable bool (explicit per damage type, Freeze 487)}.
- API: NoteOverlap(Payload) writes a "TraceOverlap" audit entry (first contact per instance and per frame-burst only); Resolve(Payload) returns FRPGDamageResult {Outcome enum: Accepted, RejectedInvulnerable, RejectedDead, RejectedStaleGeneration, RejectedDuplicate, RejectedNoTarget, Blocked; Reason FString; HealthBefore/After; bConsumed (false for invulnerable so a move may retry while still overlapping, true for accepted/duplicate/stale)}.
- Decision order inside Resolve (Freeze 12.1): validate target and generation (32.2) -> target alive -> duplicate (SourceMove, AttackInstance, HitStage, Target) -> invulnerable (single copy of the tag read; records pack tag, dodge stage, montage name and position, window source) -> guard (Status.Blocking and angle +/-65 degrees, same numbers as SM_ImpactDecision WasAttackBlocked?, stamina damage once, optional reduction) -> health once (HurtPlayer) -> lethal short circuit (Freeze 32.3) -> reaction (section 4.3) -> audit.
- Audit: ring buffer of 64 FRPGDamageAudit entries (Sequence, WorldTime, SourceMove, AttackInstance, HitStage, Stage {Overlap, Resolved}, Outcome, Reason, Amount, HealthBefore/After, PlayerMontage and position, PackTagInvulnerable, DodgeStage, Generation); counters per outcome and per move; BuildLines for URPGCombatDebug (rpg.Debug overlay) and getters for drivers.
- Moves keep their geometry (reach, blade height, LOS, jump clearance) and call NoteOverlap then Resolve; their counters (GetInvulnerableCount, GetHitCount, javelin Dodged/Hit) are derived from resolver outcomes with the same once-per-instance counting so pie_a4_low_sweep.py (14), pie_a5_heal_punish.py (31), pie_leap_wave.py (17) keep their numbers.
- Hit reaction by reflection (4.3, to be confirmed): Blueprint path is BP_Character_DamageTaken.ActivateDamageTakenAbility (2.2 item 6): build BP_HitData_C (/Game/AdvancedARPGCombat/AdvancedCombatFramework/CollisionSystem/Objects/BP_HitData; variables SourceTags, ImpactDecisionTag, Damage, HitResult, Instigator, DamageCauser, HitAngle, HitFromDirection, AttackData, Swing Direction), find the player's ability with tag Ability.HitReaction (RPGPack::FindAbilityByClassName pattern), call "Set Hit Data" then ASC "Try Activate Ability". Feasibility risks: BP_HitData construction by NewObject of a Blueprint class, pack poise side effects, AttackData null (unverified).
- Frame rate helper: static URPGInputTestUtils::SetFrameRate(float Fps, bool bFixedStep) saving previous t.MaxFPS, bUseFixedFrameRate, FixedFrameRate, bSmoothFrameRate and restoring them on call with 0 and on EndPIE (FEditorDelegates::EndPIE).
- I-frame measurement hook in URPGDodgeTiming (already ticks every frame, RPGDodgeTiming.cpp:38-71): each tick read the tag and the dodge montage position; record begin and end transitions {montage, position, real time, delta time, play rate} into a small FRPGIFrameSample list readable by drivers; expected values read from the montage's ANS_iFrames_C notify events (GetTriggerTime, GetEndTriggerTime) so nothing is hard coded.
- Guard against R1 (tag removed by the stopped quick montage while the full roll window is open): in URPGDodgeTiming tick, if a dodge montage is active, its position is inside its ANS_iFrames window and the tag is missing, re-add it through AddOwnedGameplayTag (and count it); if the tag is present with no active montage that has an open iFrames window and no other known source, remove it (stale cleanup) and count it. Idempotent.
