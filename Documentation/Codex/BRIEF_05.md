## 2. Part A: the audit (about 60 to 90 minutes), read-only
Produce `Documentation/Codex/AUDIT_01.md`, appended section by section while you work, in this order: `Pack/`, `Player/` (in this sub-order: encounter, attack tracker and rules, stagger and posture, phases, hit intake, swing tracker and weapon table, build loadout, dodge and i-frame monitor, death, look, HUD in `UI/`, the rest), `Boss/`, `Combat/`, `Audio/`, `Arena/`, `Benchmark/`.
Look for REAL defects only, each with: file:line, a quote of the lines, the concrete failure scenario (state or input, then wrong result), severity (crash, wrong behaviour in the fight, test-only, latent), and how sure you are (confirmed by reading, or plausible). Priorities:
1. Lifetime and GC: raw `UObject*` or `AActor*` held across frames without `TObjectPtr`, `TWeakObjectPtr` or `UPROPERTY`; pointers into pack arrays (`FScriptArrayHelper` raw pointers) used after a call into the pack; delegates bound without unbinding in `EndPlay`; timers that outlive the object or the encounter generation (the code uses `RPGBossEncounter::GetGeneration` to drop stale callbacks: find callbacks that do not).
2. Tick order and same-frame races: components that read each other's state in `TickComponent` without `AddTickPrerequisiteComponent` where order matters (the death component, the stagger, posture, phases and encounter were fixed once; look for others), state changes between two reads in one function.
3. State machines: a state entered but not left on some path (death, reset, respawn, interrupt, transition, stagger, riposte, dodge, build apply), counters that are not reset by `ResetEncounter`, flags set but never cleared, a path that returns before restoring what it saved (movement mode, input, collision, timers, montages).
4. Reflection call sites: names that appear once and are never verified (log or counter when missing), return values ignored, out parameters read when the call failed, enum byte values assumed (the pack's enums are bytes whose value is the position, see KI-089).
5. Numbers and units: seconds against milliseconds, degrees against radians, cm against m, divide by zero, clamps missing, NaN risks (`FMath::` on zero vectors), `float` for time (`double` is used elsewhere: find float time accumulations that lose precision in a long session).
6. Shipping hazards (Gate 4): debug code not guarded by `UE_BUILD_SHIPPING`, `UE_LOG` spam in `Tick`, console variables without a default, `LoadSynchronous` in the middle of a fight (hitching), `GetAllActorsOfClass` or `TActorIterator` in a per-frame path, allocations per frame.
7. Tests: for each pure rules header (`RPGBossMath.h`, `RPGSwingRules.h`, `RPGBuildRules.h`, `RPGAttackKind.h`, any other header-only rules file) list the branches the existing automation tests do not cover.
Rate each of the eight areas at the end of the audit: "no defect found" is a valid and useful result, say how much of the code you actually read (file list with line counts) so Claude knows the coverage. Do not report style, naming or formatting.
