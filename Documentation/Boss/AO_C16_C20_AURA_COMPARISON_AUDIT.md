**Status:** Offline readiness complete. Codex did not launch the Editor, build, PIE, cook, package, or modify content. The Lead owns runtime captures and visual review; the owner owns look approval.

## Paired capture controls and limits

`Scripts/Editor/pie_aura_comparison.py` selects and logs one route per process, resets/wakes/holds one boss, sets its health to 50% of the read maximum, places the player at a 260 cm lane from the boss, and uses the same existing `FollowCamera`. After 3 game seconds of setup settle it discards 3 startup frames and captures the approved asset. It swaps only the transient Niagara component's system to the candidate, explicitly activates it, verifies its asset path/activity, waits 3 game seconds, discards 3 transition frames, and captures the candidate. Each screenshot request uses serialized `HighResShot 960x540`; capture retries until issued and waits for a stable, readable PNG. Mean gray is logged per frame and retained frames below 5 are rejected. Candidate failure or restore/error paths remain explicit.

The script does not force a camera transform, lighting, exposure, boss orientation or elapsed world time to a common authored value. The screenshots are sequential; the camera may track/rotate, and the one-second transition allows time/exposure effects to differ. The 260 cm player lane and same camera component are setup controls, not proof that the whole boss is visible or that framing is pixel-identical. Lead must inspect both images and report deviations. The driver itself makes no visual-quality verdict. C-1104 sets DATA-default as acceptance scope; do not queue a true-legacy parry rerun just to restore route wording.

AO-C17 adds one JSONL manifest record after each PNG is confirmed. Each line records run tag, requested route, frame label, active Niagara asset path, health/max health, camera identity and position, control rotation, spring-arm pivot position, PNG path, `png_exists`, and decoded mean-gray value. Read failures are represented as `UNKNOWN`; a reused run manifest is refused. Screenshots and manifest are written under `D:/FightVideo/aura_compare/<route>/` with the run tag in each filename, following `P_SHOWCASE/pie_showcase.py`'s absolute-path convention. The exact `HighResShot` command is logged and each frame wait is bounded at 20 seconds, including stable-file/readability polling. This JSONL is a frame receipt, not a standalone run-identity receipt: pair it with Lead's same-run activation-witness line, build/configuration/stage identity, and log hash, because the Editor-side driver cannot prove those itself.
