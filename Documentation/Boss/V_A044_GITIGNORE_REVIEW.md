# V-A044: .gitignore Review & Cleanup Proposal

**Author:** Antigravity (Offline Quality, Audit & Asset Lane)  
**Date:** 2026-11-06  
**Scope:** Review of root `.gitignore` rules, identification of untracked transient artifacts, and hygiene proposals.
**Sources:** .gitignore, Documentation/KNOWN_ISSUES.md:301

---

## 1. Executive Summary

- **Audit Target:** Root `.gitignore` in `OneBossFight`.
- **Finding:**
  - `.gitignore` robustly protects third-party marketplace packs (`Content/Paragon*/`, `Content/MS/`, `Content/BeamPack/`), editor caches (`Saved/`, `Intermediate/`, `DerivedDataCache/`), and large reference video footage (`*.webm`, `*.mp4`).
  - **Identified Gap:** Transient root build logs (specifically `build_raw.log` generated by command-line builds) and temporary python/agent scratch folders are not currently explicitly ignored at the repo root, causing them to linger in `git status` untracked files.

---

## 2. Recommended `.gitignore` Updates

```gitignore
# Transient root build logs generated during unattended engine compilation
/build_raw.log
/*.log

# Agent & scratch workspaces
/scratch/
/.agent_scratch/
```

---

## 3. Benefits & Risk Assessment

- **Benefits:**
  - Eliminates the recurring risk of accidentally staging `build_raw.log` (prohibited in `[C-925]`).
  - Keeps `git status` clean and focused solely on active project deliverables.
- **Risk:** Zero risk; build logs are diagnostic outputs and must never be committed to git history.
- **Status:** Documented as a proposal awaiting Lead/Owner approval before applying to `.gitignore`.
