# Queue BB Batch 8: X36–X40 Framework Audit

Static source and documentation audit. No Unreal, build, PIE, Shipping build, or performance capture was run.

## Findings

| Task | Status | Source-backed finding / failing scenario |
|---|---|---|
| X36 Sevarog parry contact | **OK, source path only** | The pack parry observer is attached to pack bosses (`RPGPlayerMovesSubsystem.cpp:879–881`) and observes their pack trace hit set (`RPGPackParryContact.cpp:150–184`). Sevarog's executor does not depend on that observer: each active blade window calls `URPGDamageResolver::Resolve` (`RPGFrameworkMoveExecutor.cpp:303`), whose common policy checks `URPGPlayerParry::IsParrying`, spends a parried hit key, and calls `NotifyParried` (`RPGDamageResolver.cpp:154–160,188–192`). This proves a source route exists, not that Sevarog's authored sockets overlap the player's parry volume or that the animation window is timed correctly. Lead PIE still owns the actual contact gate.
| X37 damage-policy parity | **OK with scope boundary** | Framework attack damage to the player uses the same `URPGDamageResolver` policy path as project-authored pack-boss contacts (`RPGFrameworkMoveExecutor.cpp:303`; `RPGDamageResolver.cpp:143–160,168–200`), so stale/dead/duplicate, i-frame, parry and block outcomes are centrally decided. Player attacks against a native-health framework boss take the separate `IRPGNativeBossHealth` route and bypass pack damage execution/scaler/components (`RPGHitIntake.cpp:533–557,683–700`). Do not claim full bidirectional parity from the shared outgoing resolver alone; incoming native boss-health behavior is an explicit separate contract.
| X38 Shipping test-hook exclusion | **RISK: reflected no-op hooks remain** | Framework bridge declarations are gated by `WITH_EDITORONLY_DATA` and test bodies have Shipping guards (`RPGFrameworkBossCharacter.h:23–38`; `.cpp:66–82,161–194`). Greystone startup CVar/implementation are excluded by `!UE_BUILD_SHIPPING` (`RPGPlayerMovesSubsystem.cpp:102–109,363–367`). However `ResolveForTest` and `NoteOverlapForTest` are still declared as unguarded `UFUNCTION`s (`RPGDamageResolver.h:190–193`); their `.cpp` implementations are no-op/unavailable in Shipping (`:248–270`). If “exclusion” requires no Shipping reflection surface, this fails that stricter gate. No Shipping binary/UHT inventory was run, so Shipping exclusion is not fully proven.
| X39 executor tick cost | **RISK: formatting/allocation candidates** | Normal blade contact resolves through `KeyOf`, which formats a new `FString` on each `Resolve` (`RPGDamageResolver.cpp:37–40,143`). Enabled channel ticks also create a formatted `FString` then intern it as an `FName` for `ChannelTick_n` (`RPGFrameworkMoveExecutor.cpp:500`) and format a log outcome (`:514`). These are actual string-construction sites in hit/tick paths, but no allocation profiler or frame-time capture was run; no performance impact is claimed. If profiling shows material cost, precompute tick keys or use a non-string key representation before optimizing.
| X40 new-boss checklist | **DONE, path corrected in closeout** | Added a Sevarog framework-proof evidence map to `NEW_BOSS_CHECKLIST.md`, separating C-1256a spawn/S1, C-1258a S1–S3, C-1262a four-card/combo, and C-1274 add-on code proof from remaining Lead PIE, integration, and owner-data gates. A subsequent path inventory found the C-1262a folder's actual name is `C1262A_SEVAROG_DIAG`; the initially entered longer path was corrected in the checklist and this report. It explicitly names the framework route as an add-on to generic definition workflow rather than presenting it as an already wired data-route boss.
