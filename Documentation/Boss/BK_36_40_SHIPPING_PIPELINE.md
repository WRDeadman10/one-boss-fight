# BK-36–40 — Shipping pipeline and receipt tooling

Added `Scripts/Editor/run_bk7_shipping_pipeline.ps1`. Its default is preflight-only; execution requires `-Execute`, an explicit build ID, and the approved reflection-dump executable/argument list. Preflight and the execution path refuse either C-1155 lock and any running UnrealEditor process; the runner acquires both locks with a per-run owner token, uses a unique task-specific stage path, and releases only locks whose owner token still matches. It never deletes an existing stage or evidence directory.

The execution path calls UAT for Win64 Shipping cook/stage/archive, captures a caller-supplied UHT/reflection-dump command output, then runs `CheckShippingBinary.py`, `CheckShippingFeatureSymbols.py`, and `check_shipping_guards.py` against the staged binary/source. Its JSON receipt records the explicit build ID on the UAT log, binary, and reflection dump; records hashes and binary size; includes target/configuration, source HEAD and dirty-file count, check exits, and `shipping_smoke=NOT_RUN`. The exact dump command is intentionally supplied by the Lead/runner caller; the script does not guess a version-specific UHT reflection-dump CLI.

Added `bk7_shipping_receipt.schema.json` and `verify_bk7_shipping_receipt.py`; validation rejects mixed artifact build IDs, malformed/mismatched hashes, nonzero checks presented as PASS, and any packaged-smoke claim. Tests: runner source contract 5/5; receipt tests 5/5 including artifact hash recomputation; PowerShell parser and JSON parse pass.
