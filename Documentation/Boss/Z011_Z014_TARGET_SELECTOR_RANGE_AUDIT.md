## Z011 — target invalidation

`ARPGFrameworkBossCharacter::TargetFault` checks weak controller/target validity, pending destruction, controller/pawn ownership and same-world identity, optional arena leash, readable finite health, then positive health (`Boss/RPGFrameworkBossCharacter.cpp:111–120`). During the main tick, an off-arena target with `bArenaLeash` enabled enters `HandleLeash`; when the target returns valid, the boss resumes its walk-to-band flow (`:251–260`). Other invalid/dead/unreadable target states or changed health fail closed as `Framework.Boss.TargetLifeOrHealthChanged` (`:261–265`). This does not reacquire another player or survive a dead/destroyed target; an invalid weak target has no further target-position work after that guard. Missing target, destroyed, wrong controller/pawn/world, off-arena leash and dead/unreadable health are represented in source branches, but retained unit tests do not establish end-to-end lifecycle for each. Arena leash/fail behavior belongs to the framework fixture profile, not a claim about legacy pack AI.

## Z012 — weighted action selection

For each card, the move model hard-filters encounter/generation, card validity, target validity, neutral/idle state, snapshot domain, matching phase, inclusive per-card horizontal range, front cone (including optional hysteresis), optional vertical separation, and stale frame/clock (`Player/RPGBossMoveModel.cpp:13–43`). Selector then applies per-card cooldown; eligible score is `weight × range factor × repeat factor × context pattern` (`Player/RPGBossMoveSelector.cpp:33–68`). Range factor is 1 at midpoint and falls to 0.5 at each authored endpoint; repeat penalty applies to recently started card indices. Context can multiply for kite/hug/back-dodge/greed/preferred aggro band. Deterministic first-index wins ties when `TieBand=0`; positive tie band chooses from the top-score tier using the configured seed plus successful-start count (`:70–80`). Cooldown/history is recorded only after `NoteStarted`, not on eligibility/decision (`:84–89`).

Named tests include `Framework.Selector.Init`, `.Policy`, `.BoundedTie`, `.EligibilityProperty`, `.PatternMultipliers`, `.ConeHysteresis`, reset/replay and score-domain cases (`Tests/RPGBossMoveSelectorTests.cpp`), plus MoveModel phase/range/cone/vertical/stale/generation boundaries (`Tests/RPGBossMoveModelTests.cpp`). These are synthetic pure-rule tests, not runtime tuning or pack-BT selection evidence.

## Z014 — no-valid-action recovery

The selector returns a successful decision call with `ChosenIndex == INDEX_NONE` when every card is filtered; no random or implicit fallback is chosen. The framework caller logs each eligible/refused trace. Recovery order is: optional in-place turn if in-band with no card and `RepositionMax>0` (bounded to 3 s); optional walk back to the band while reposition attempts remain; optional neutral strafe if `NeutralStrafeSeconds>0`; otherwise fail closed with `Framework.Selector.NoCandidate` after budget exhaustion (`Boss/RPGFrameworkBossCharacter.cpp:470–518`). A candidate found after neutral strafe ends that mode; only an actually started card advances selector cooldown/repeat state (`:518–526`; selector `:84–89`). Failure of walk-controller acquisition or walk request fails closed immediately. Target invalidation has its separate leash/failure handling above.

`RPGBossComboFallbackTests.cpp` covers a combo candidate refused by the model and transition to a fallback candidate; selector tests cover pure no-candidate and gating. Historical `KNOWN_ISSUES.md` KI-149 records a two-card/cooldown profile exhausting all candidates and hitting fail-closed `NoCandidate`; later mitigation adds phase cooldown starvation validation and opt-in neutral strafe. Strafe-stuck turn flip is unit-tested but historical live run emitted no `strafe_stuck` event (C-712). The recovery paths are framework-specific; legacy pack AI's no-action behavior is not established by these tests.
