# BK-31–35 — Framework performance attribution

Added default-off Development telemetry `rpg.Perf.FrameworkAttribution`. When enabled, an RAII scope measures inclusive wall-clock CPU time for `URPGFrameworkMoveExecutor::TickComponent`, including its early-return paths. Saturating counters aggregate sample count, total microseconds, and maximum microseconds; a machine-readable `[FrameworkPerf]` line emits when the nominal five-second window has elapsed, with run GUID, engine version, map, and sample start/end. The CVar and sampling work are compiled out of Shipping, and no timer/counter/log work runs when the CVar is off.

GPU timing cannot be attributed to this actor-component scope. The line explicitly emits `gpu_component_ms=NA gpu_attribution=unavailable`; the benchmark runner's existing `gpu_ms` remains a frame-global measurement and must not be represented as boss/framework GPU cost. The executor log also marks `project_build_id=unavailable`; a receipt must be joined to the exact project binary/build externally before acceptance.

Added `RPGFrameworkPerfAttribution::FWindow` as a pure saturating counter helper and native automation test `OneBossFight.Framework.PerfAttribution.CounterMath` for accumulation, invalid samples, reset, and overflow boundaries. The native test is authored but unrun because the Lead still owns the engine window. The offline source guard passed 4/4, receipt verifier tests passed 6/6, prior BK-26–30 and BE-X36–40 contracts passed 5/5 and 6/6, Python compilation passed, and scoped `git diff --check` passed. No native build, benchmark, GPU capture, or engine run is claimed.

Added `framework_perf_attribution.schema.json` and `verify_framework_perf_receipt.py`. The receipt requires explicit target RTX 2060 Super vs proxy/unknown classification, build/run identity, sample window, unit-labeled CPU scopes, and GPU frame-global value separately from a hard false component-attribution flag. Synthetic validator cases pass; receipts with a component-GPU claim fail closed.
