## Unreset fields and findings

1. **Actionable lifecycle gap, test hooks:** `ProofGStart` and the I-frame hook group (`ProofIFStart`, `ProofIFPressAt`, `ProofIFProbes`, `bProofIFPressed`) are not reset by `RestartEncounter`. Their per-hook initialization happens only when the start is negative at a later first decision (`cpp:535–536`). If death/success occurs while a configured hook is still active, the active start survives, so the next generation can skip arming or continue a prior generation's timeline. This is bounded to non-shipping proof hooks, but is a real restart-isolation defect. Suggested hotfix: clear guard start to -1 and reset the four I-frame fields in the restart block, then add a restart regression for an interrupted hook. **No code changed by this audit.**
2. **Unreset but currently guarded/inert:** `StaggerEndsAt`; F11 timestamps/state enum; flask timestamps; combo pause deadline; `OverlayLoggedAt/OverlayLastState`; proof-hook arrays after their start fields/counters are reset. No gameplay use across restart was found because the corresponding active flag/start is cleared or the values are replaced on the next arm. Overlay may skip one duplicate state line for up to one second after a rapid restart.
3. **Intentional actor/encounter lifetime state:** `DecisionSeq` (explicit header contract), `ArenaOrigin`, `WalkStart`, `EncounterId`, profile dependencies/target references, and `ComboGateCounter` remain stable/monotonic across generations. `bInitialized` remains true, while `bFailed` is terminal and `CanRestart` refuses it.
4. **Terminal paths:** Die/Fail intentionally stop tick-driven state, abort the executor, stop owned movement and stop F11 animation; they clear reposition-turn and parry-recovery state but do not bulk-reset the object. Die clears F11 active flags; Fail leaves them set in the terminal actor. EndPlay additionally releases dependency/weak-reference members. Do not infer a full field reset from terminal status.
