# Offline tool write-boundary audit (D68)

Date: 2026-11-03. Searched all maintained `Scripts/Tools` CLIs and traced output paths, atomic helper calls, parent-directory creation, and cleanup. Maintained tools that intentionally write project/selected output paths:

| Tool | Exact write boundary | Publication/cleanup behavior |
|---|---|---|
| `evidence_pack.py` | Creates requested output directory; copies selected logs/states and publishes `SHA256SUMS` and `evidence_manifest.json`. | Payload/manifest files use `atomic_create_copy` / `atomic_create_text` (no overwrite); manifest last. Existing output directory may remain empty or partially populated on a later failure; there is no pack-wide rollback. |
| `evidence_summary.py` | Creates output parent and writes requested CSV. | Builds complete CSV in memory, then `atomic_write_text` replaces destination; replacement is atomic per file, but output parent remains on failure. |
| `make_source_manifest.py` | Creates output parent and writes requested Source hash manifest. | Serializes then `atomic_write_text`; atomic replacement per file. Output inside Source can be self-included if it exists before traversal, as D61 documents. |
| `token_coverage.py` | Optional `--samples-output` parent and JSON sample manifest. | `atomic_write_text` replaces that one file; missing explicit logs can still result in a report/manifest with exit 0 per S173. |
| `new_rule_scaffold.py` | Creates three new source/test/reference files under the chosen output root. | Each uses `atomic_create_text`, refusing existing destinations; individual files are atomic, but multi-file creation is not a bundle transaction and earlier created files can remain if a later create fails. |

`atomic_io.py` is a shared support module, not a CLI: writes a uniquely named same-directory temp, flushes/fsyncs, then uses `os.replace` for replacement or exclusive final creation for create-only operations. Owned temporary paths are removed on exceptions. This guarantees per-file publication, not directory rollback or durability of all parent-directory metadata.

The remaining maintained CLIs are stdout-only reports or read-only scans/parsers; their filesystem reads do not mutate input files. Tests and fixtures write under temporary directories. This is source review, not a denied-permission/locked-file execution test; OS error behavior remains dependent on the specific CLI's exception handling. No project evidence, manifests, source files, or retained logs were generated by D68.
