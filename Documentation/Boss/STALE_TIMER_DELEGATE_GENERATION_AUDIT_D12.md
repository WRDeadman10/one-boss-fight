# Stale timer and delegate generation audit (D12)

## Scope and conclusion

Reviewed framework boss/executor restart and the adjacent encounter, damage-intake, and stagger callback paths. Framework move progress/watchdog use component Tick and model callbacks require the current attack token. Two next-tick paths need reset-boundary coverage: native boss hits are queued without generation metadata and finalized on the next tick; stagger riposte start is UObject-lifetime/state guarded but carries no generation or request identity and retains no timer handle. These are source-level stale-work risks, not reproduced failures. Cosmetic callbacks are separated below.

## Bounded test recommendations

1. Use a synthetic model fixture to exercise stale `Abort` and `AdvanceObservedLocal` after reset and after a new generation starts; assert `MoveModel.StaleCallback`, empty events, and live new token.
2. Exercise a `RPGDamagePayload` stamped with generation N after the life provider reports N+1; assert `RejectedStale`, unchanged health, and no duplicate/spent-key mutation.
3. Add a stagger fixture case that schedules next-tick riposte start, calls `AbortStagger`/encounter reset before dispatch, then drains the next tick and verifies no input lock, montage start, capsule-ignore state, or impact.
4. Add a second stagger case where a later riposte reaches Down before the old callback runs; this distinguishes a true per-request guard from the current `bRiposteRunning`/phase guard.
5. Queue a native player hit, reset the encounter before `FinalizePending`, then dispatch it. Specify whether reset cancels old pending hits or applies a captured generation check; assert health, posture, bleed, `OnBossHit`, and pending-queue behavior.
