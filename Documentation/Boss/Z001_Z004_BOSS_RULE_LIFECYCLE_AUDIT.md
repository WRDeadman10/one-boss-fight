# Queue Z Batch 1 — boss rule and lifecycle audit

Status: source and test inventory completed; read-only audit, no Unreal test execution. Scope: Z001–Z004 from `QUEUE_Z.md`. Production component paths are distinguished from framework proof-harness paths.

## Z001 — phase transition authority

Production authority is `URPGBossPhases` (`Source/OneBossFight/Player/RPGBossPhases.cpp`): `ResolveNow` gathers dormant, staggered, phase-two and in-transition flags and reads current/max health (80–95); failed attribute reads yield `NotReady`. Tick returns while a transition is active (134–140), dormant (142–145), health is missing/invalid/dead (146–149), or phase two already began (151 onward). Before resolving a phase-one crossing it waits for player `URPGHitIntake::HasPendingRecords()` to clear (153–163), so a same-frame posture break can be observed first. A crossing starts immediately at 166–169; a crossing during stagger is resolved as queued and `TryStartQueuedTransition` is called by `URPGBossStagger::EndStagger` (phase resolver 98–112; stagger 475–486).

`StartTransition` sets `bPhaseTwo` and `bTransition` before cancelling offence and applying the optional posture hold (243–268); completion clears transition, removes immunity/hold, checks death before buffs/resume, then applies buffs and resumes behavior (322–347). This is a one-way latch during ordinary combat, not a permanently one-way lifecycle: `ResetPhases` removes buffs/immunity, releases posture hold, and clears `bPhaseTwo` (526–551). Encounter reset calls it only after reset refusal/generation guards (Encounter 328–366). Pure test coverage is `OneBossFight.Boss.TransitionRules` (`RPGAutomationTests.cpp:195–246`): threshold equality, above threshold, dead, not-ready maximum, queued-under-stagger, already phase two, dormant, and dead flag. Missing explicit pure cases include invalid/non-finite health/fraction and queued transition resolution with transition/dormant/dead combinations; component-level test coverage is in `RPGBossPhasesClusterAdaptersTests.cpp` and `RPGBossPhaseFlowAdaptersTests.cpp`, but those adapter fixtures do not establish live packaged behavior.

## Z002 — health ownership

`URPGBossEncounter::TickComponent` applies `BossMaxHealth` after the pack attributes become readable. If current max already equals the configured max it latches applied; otherwise it writes the max, verifies readback, and scales current health by `Current * BossMaxHealth / Max` (Encounter 114–131). A separate startup correction restores full current health when the pack overwrites its initial 500 while the boss is still asleep (lines 99–112; confirm exact startup context in source). This is not the general death/reset path.

`ResetEncounter` refuses while `URPGBossDeath::IsDeathActive()` (328–337), refuses generation overflow before side effects (338–346), and on an accepted reset writes current health to the current maximum at lines 411–415, then restores poise/posture/bleed and broadcasts reset (416–438). Death handling is therefore owned by the pack/death component; encounter reset intentionally will not resurrect an actively dying boss. `URPGBossStagger::ApplyCritical` treats health <= 0 as death and avoids resuming behavior (857–869); during an active stagger it detects health increasing as a pack reset and ends the break (871–878). These code paths do not prove which external pack event initially writes health or activates its death ability; runtime ownership/order remains a Lead-run question.

## Z003 — posture thresholds and reset actions

The project posture pool defaults are 100 maximum, 6 seconds regeneration delay, 13 points/second, and pack-poise pin enabled (`RPGBossPosture.h`, fields `PostureMax`–`bPinPackPoise`). Damage is ignored for nonpositive amount, dead/dormant boss, or invalid negative pool; held pool suppresses and counts drains; otherwise it clamps at zero and requests a single break through `RequestBreak(false)` when reaching zero (`RPGBossPosture.cpp:90–120`). There is no configurable break threshold below zero: zero is the threshold. Break gating then rejects dead, dormant, transition, already staggered, and cooldown states in the shared rule ordering tested by `FRPGTransitionRulesTest` (RPGAutomationTests.cpp:201–220).

Reset actions: encounter reset clears hold and held value, fills the pool, and makes regen immediately eligible (`ResetPool`, Posture.cpp:140–146); normal stance-break end refills and restarts regen delay (`RefillAfterBreak`, 148–158; `EndHold`, 182–192); phase-transition hold pins current value and normal completion releases without refill, restarting delay (`BeginHold`/`EndHold`, 170–192; Phases.cpp:254–259, 327–330). The pure `OneBossFight.Boss.PostureRegen` test covers timing, cap, zero-held vs dropped-break zero, immediate initial regen and second drain (RPGAutomationTests.cpp:253–300). Source docs and defaults match those figures; configured component values may be overridden per actor/profile, so CDO numbers alone do not establish the shipped boss instance values.

## Z004 — attack cancellation lifecycle

`URPGAttackTracker` ends a live tracked instance when disabled, animation disappears, boss health reaches zero (polled on a 0.1-second accumulator), montage stops, or a different attack replaces it (RPGAttackTracker.cpp:357–407). A new attack is vetoed when staggered, transitioning, dormant, or waking if `bVetoIllegalStarts` is enabled; veto stops montage and clears tracker phase/index (422–446). Branch denial likewise stops and clears (449–465). Transition cancellation is delegated through `RPGBossInterrupt::CancelOffence` before transition presentation (RPGBossPhases.cpp:252–254). Death behavior in tracker ends its own instance and returns but does not itself stop the pack’s death montage (378–395). `EndPlay` restores altered telegraph montage rate, then calls superclass (351–355).

Stagger death path stops only stagger-owned montages before ending the stagger (Stagger.cpp:864–869); general `AbortStagger` clears cooldown/riposte state, stops owned montages if active, ends without resuming behavior, and releases/refills posture (825–840). EndPlay only sets the stagger phase idle (843–847), relying on actor/component teardown for outstanding resources. Coverage located is primarily adapter/preflight tests and shared pure gate tests; no static test inventory found that proves all runtime cancellation races (death concurrent with transition, teardown during each montage stage, tracker disabled while montage blends, and ability-owned tasks). These remain explicit runtime/test gaps, not confirmed defects.
