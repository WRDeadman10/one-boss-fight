# Combo pause state audit (D14)

## Flow and fresh snapshot

`HandleComboGate` runs only after the finished executor is clean and evaluates the graph with a fresh `MakeSnapshot()` at the card boundary (`RPGFrameworkBossCharacter.cpp:600-601, 762-790`). For a Continue edge with positive pause and a resolved candidate, it sets `bComboPausing`, an absolute `ComboPauseUntil = WorldTime + PauseSeconds`, and `ComboPendingCard`, then returns without rearming the executor or incrementing the attack ordinal. The component tick keeps ticking. Once `WorldTime >= ComboPauseUntil`, it calls `StartComboCard` (`:600`), which clears the pause/pending state, builds a second fresh snapshot (`:803-805`), increments `AttacksDone`, prepares the executor, and attempts the chosen card. On success, it updates selector start memory and combo outcome baselines (`:809-815`).

Both snapshots are fresh: branch selection uses current range/yaw at the prior card's completion; the actual start uses target location, phase, generation, frame, and world clock at pause expiry (`MakeSnapshot`, `:754-761`). The start route bypasses selector candidate choice and cooldown filtering by design, but the move model revalidates state, card, target, phase, range/cone/vertical constraints and monotonic snapshot through `StartCard` (`RPGFrameworkMoveExecutor.cpp:121-128`, `RPGBossMoveModel.cpp:50-89`). If the target moved out of the card's valid range/cone or other start predicates changed, the attempt is refused and the combo ends; a later tick can use the ordinary selector.

## Cancellation and interruption

| Condition during pause | Current behavior | Coverage / test needed |
|---|---|---|
| Stance break | `StartStagger` cancels `bComboActive`, `bComboPausing`, and `ComboPendingCard` (`RPGFrameworkBossCharacter.cpp:693-705`). | No actor test pauses, causes a break, then advances beyond the old deadline to assert no continuation; add that case and inspect one-shot cancellation. |
| Target invalid/dead/health drift | Every boss tick validates the explicit target before pause dispatch (`:248-263`); invalid target/health calls `Fail` and terminal tick returns (`:886-891`). Combo flags are not explicitly cleared in `Fail`, but no later tick dispatches them; restart is unavailable after failure. | No state assertion/test for pending-card cleanup on terminal failure. Decide whether terminal flag gating alone is the contract or clear pause state explicitly. |
| Target outside authored arena with leash enabled | Tick calls `HandleLeash` and returns while target remains off arena (`:248-251`); leash code does not cancel a finished-card combo because executor `DidFinish()` is true (`:205-227`). `ComboPauseUntil` is absolute world time, so it continues to expire while leashed; on target return, the still-pending combo can start immediately if the deadline passed. | Source-level behavior; intended semantics are not specified. Add a test where leash begins during pause, target returns before/after expiry, and assert whether pause time counts while away. |
| Target moves but remains valid/in arena | Pause remains active until absolute deadline; at expiry `StartComboCard` snapshots current geometry and generation, not the old gate snapshot. | No delayed-start test mutates range/yaw/phase/target during pause. Add in-band success, out-of-range refusal/fallback, cone refusal/fallback, and unchanged-state control. |
| Boss dies, fails, is destroyed, or encounter restarts | `Die`/`Fail` are terminal tick gates, `EndPlay` aborts executor and drops dependencies, and successful `RestartEncounter` resets combo and pause flags (`:855-890`, especially `:864`). The old deadline is not explicitly cleared on death/failure/EndPlay, but cannot be dispatched after those gates; restart clears the pending card/flag. | No pause-specific death/failure/restart/EndPlay test. Assert no continuation after each terminal path and confirm a new generation starts with no pending combo. |

## Existing tests and evidence boundary

`RPGBossComboTests.cpp:42-45,66-71` covers pause-domain validation and propagation on a pure edge step. BUILD-125 has live evidence for the ordinary 1 s pause/resume route and normal combo completion (`TEST_PLAN.md:478`). Neither proves cancellation or target/state mutation during the pause. No inspected automation test calls `HandleComboGate`, waits for a paused actor, or calls `StartComboCard`; no code change or test/build/Editor run was made for D14.

## Bounded integration cases

Use the D13 asset-backed transient world fixture when a combo-capable proof profile is available. Cover: (1) no-pause edge starts next card immediately; (2) pause expiry starts with fresh in-range snapshot; (3) range/cone change refuses and normal selector recovers; (4) stance break clears pending state and no later start occurs; (5) leash pause expiry/return semantics; (6) target invalidation/death, boss death/failure, EndPlay, and successful restart suppress stale continuation. Capture `combo_gate`, `combo_pause`, `combo_pause_end`, `combo_end`, `playback_start`, token generation, frame/clock, and selected candidate; do not treat logs alone as internal state assertions.
