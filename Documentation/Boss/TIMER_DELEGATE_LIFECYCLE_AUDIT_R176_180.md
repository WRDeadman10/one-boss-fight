## Findings

1. **Conditional cleanup gap — Enhanced Input bindings:** DodgeTiming, PlayerParry, and RiposteInput bind directly to the pawn's `UEnhancedInputComponent` but store no binding handle and do not remove their bindings on EndPlay (`RPGDodgeTiming.cpp:129`, `RPGPlayerParry.cpp:54`, `RPGRiposteInput.cpp:45`). The current subsystem attaches each feature once per pawn, so normal pawn destruction also destroys its input component and no active failure was established. If a component is ever detached/recreated while its pawn/input component survives, old bindings can remain in the input component; store/remove handles or document that this lifetime is unsupported.
2. **Uncancelable delayed visual:** the director's strike Niagara timer uses a local handle and weak world/effect captures (`RPGSevarogDirector.cpp:79–91`), so it is memory-safe but not canceled by director EndPlay. A late flash after encounter teardown is possible while the world persists. No owner reference is captured.
3. **One-shot component callbacks:** Look, Stagger and HitIntake use UObject-bound next-tick callbacks and have no stored timer handles (`RPGBossLook.cpp:31`, `RPGBossStagger.cpp:572`, `RPGHitIntake.cpp:465,506`). Their callbacks guard state/ownership, but explicit cancellation is absent. The source scan cannot prove whether the engine clears those callbacks during dynamic component removal before UObject destruction; no raw pointer capture or persistent repeating callback was found.
4. **Paired/removable paths verified:** Landed delegate, actor-spawn handlers, `OnHit`, core ticker, and test UObject listener all have a matching removal path.

Static source review only; no runtime behavior, engine timer semantics, build, or tests were exercised.
