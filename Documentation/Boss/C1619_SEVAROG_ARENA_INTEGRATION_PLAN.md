# C-1619 Sevarog arena integration

## Current source boundary

- `URPGEncounterSelectionSubsystem::BuildWorldBindingInternal` counts actors already in the world. A framework selection requires exactly one `ARPGFrameworkBossCharacter`, exactly one local pack player, and zero competing pack bosses. The selection subsystem does not spawn the boss.
- `URPGPlayerMovesSubsystem` runs the selected-world activation and calls `InitializeSelectedEncounter` on the selected framework boss. That production API sets `bTestInitialized=false` and `bSelectedRouteInitialized=true`.
- `ARPGFrameworkBossCharacter::Tick` runs the normal selector. It only skips the selector at the neutral gate when `bTestInitialized` is true; production `InitializeSelectedEncounter` passes false. `InitializeSelectedEncounterForTest` is a different, test-only entry point.
- The current user-observed default is `DA_Sevarog_G044_Encounter`, which is an Ember/pack definition. The report/log observed `BP_AdvancedGameMode_C` spawning `BP_ExampleGreatSwordBoss_C_3`; selected framework startup cannot succeed while that competing pack boss remains in the world.
- `rpg.EncounterDefinition` and `rpg.FrameworkEncounterSelection` are cheat cvars with default-off behavior. The definition cvar is compiled out in Shipping, and the startup comments explicitly preserve the legacy route by default. They are diagnostic/dev selectors, not a production route.

## Recommended production route

Use a configured encounter route owned by the actual arena GameMode/startup coordinator, with `DA_Sevarog_Framework_Encounter` selected through a persistent production setting that exists in Shipping. At startup, resolve and validate that definition before spawning any boss. For a framework definition, spawn exactly one `ARPGFrameworkBossCharacter` (or a thin child BP only if presentation overrides prove necessary) at the arena's authored boss start transform; do not spawn `BP_ExampleGreatSwordBoss_C_3`. For the existing Ember route, preserve the current pack spawn behavior. Keep the pack boss class and its source assets in the project for other routes; the Sevarog branch must simply not instantiate that class.

The least ambiguous first implementation is a named boss start actor in `L_SevarogArena` plus an explicit GameMode route enum / selected definition asset. The startup coordinator resolves the route and spawns the selected boss before `BuildWorldBindingInternal` runs. This avoids depending on actor class defaults or editor-only cvars. Keep the placed start marker as data only; do not place both candidate boss actors in the active map, since the census is world-wide and would refuse the competing pack boss. If the project instead requires a placed boss, the GameMode must skip the pack spawn and the startup coordinator must bind the one placed framework instance; do not rely on hiding it.
