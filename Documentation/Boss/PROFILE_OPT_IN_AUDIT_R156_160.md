# Profile opt-in gate audit (R156–R160)

Scope: positive-value gates on `URPGBossFrameworkProfile` floats, plus tightly coupled zero-default groups they activate. Defaults and validation below are read from `RPGBossFrameworkProfile.h` / `RPGBossFrameworkProfile.cpp`; runtime state claims are source inspection only. This is an inventory, not live proof.

Lifecycle references used below: initialization in `RPGFrameworkBossCharacter.cpp:66–82`; encounter-generation reset in `:861–864`; terminal handling in `:874–895` (`Die`, `Fail`, `EndPlay`). `Initialize` and restart clear state; `Die`/`Fail` stop future encounter work and clear pending parry recovery/reposition state; `EndPlay` aborts the executor and drops dependencies. A “none” reset cell means the setting is consumed as immutable profile data and has no feature-owned runtime accumulator.

## Scope notes

- The matrix also includes paired groups whose runtime guard is expressed as a bool/count plus a positive float (dodge history, arena leash, repositioning), so their supporting cells are not lost.
- Boolean opt-ins (`ParryFairTelegraph`, `bAggroEnabled`, `bPhaseSupersedesStagger`, `bRangeBandPartition`, `bParryGradeScale`) are outside the literal positive-float query. Their profile defaults and references are listed in `REF_PROFILE.md`; the aggro, fair-telegraph, and phase lanes have schemas and feature references. S189 added the missing F5-only refusal for `bRangeBandPartition`; see `OPT_IN_DEFAULT_OFF_AUDIT_S189.md`.
- Log-token schema/index completeness is also checked mechanically by `python -I Scripts/Tools/check_validator_tokens.py`; at this audit it reports 138 source tokens, 138 schemas, and complete semantic/emission indexes.

Audit result at S156–S160: every listed positive-float gate had a finite/domain or paired-field validation path, documented default, reset/immutable-state disposition, and feature telemetry/schema or explicit observability limit. S189 separately audited boolean defaults and group gates and found/fixed the missing F5 refusal for `bRangeBandPartition`. No reset omission was found in the state-bearing listed groups. The one observability limitation is `SelectorTieBand`: no dedicated activation token exists; its seeded outcome is witnessed by comparing `decision` sequences under known profile seeds.
